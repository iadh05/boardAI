## Demo — try it yourself

1. `docker compose up -d nginx`, `pnpm dev`, open http://localhost:8080 → the address becomes `/room/<id>`; the header says **Connected · Just you**.
2. **Copy link**, open it in another browser (or a private window) → header says **2 here**.
3. Add a box in one window → it appears in the other. Rename it in the other → the first one updates.
4. Move your mouse over the board → the other window shows your cursor with your guest name.
5. Drag the same box in both at once → it settles on the same spot in both.
6. Turn the network off in one (DevTools → Network → Offline) → **Offline — your edits are kept…**; add a box; turn it back on → the box appears in the other window.
7. Ctrl+Z in one window → only that window's last change goes away.

## Things worth knowing (learned building it)

- **Two valid edits can make an invalid board together** (a box deleted while someone connects to it). The read side repairs it; the document keeps the raw state. Tested with two docs synced both ways.
- **Tabs of one browser sync by themselves** (y-websocket's BroadcastChannel). Turned off: "Connected" must mean the server has it. The e2e uses separate browser contexts for the same reason.
- **An unhandled socket `error` crashes Node.** A refused connection reset by the client would have taken the whole server down; found by repeating the server tests 80 times.
- **The browser knows it's offline before the WebSocket does.** Without listening to `offline`, the badge said "Connected" for up to 30 s.
- **The y-websocket client relays other people's presence**, so "who sent it" doesn't say whose cursor it is — the server's tests disable that path to test the server alone.
